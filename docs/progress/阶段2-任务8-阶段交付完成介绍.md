## 4. 资产安全十问结论

1. 余额和 `balanceAfter` 不会为负：条件扣减、V10 CHECK、40 路并发测试共同保证。
2. 重复业务号不能换用户、方向或金额：服务校验完整幂等身份，冲突返回 `47002`。
3. 同一扣分不能用不同编号冲正两次：原流水唯一冲正索引和状态校验共同阻止。
4. 积分与库存不会只成功一边：兑换创建和冲正处于同一 MySQL 事务，故障测试证明全回滚。
5. 20 路重复兑换只产生一个订单、扣分和库存消费：并发测试已验证。
6. 用户不能查询他人资产：用户 ID 来自登录上下文，查询强制 self scope，7 个接口有真实鉴权链测试。
7. 兑换不能使用 `MALL` 或 `LOTTERY`：编排服务固定写入 `POINTS`。
8. 商品改价不会改历史：兑换单保存商品、SKU、价格和图片快照。
9. SQL、重复键和溢出原文不会泄漏：业务翻译为 `47001-47009`，全局异常处理返回安全错误。
10. V1-V9 未修改，抽奖、Outbox 和权益保持可用：迁移差异检查和 312 个全量测试通过。

最终审查：Critical 0，Important 0。

## 5. 现在能做的真实例子

管理员可以给用户增加 5000 积分；用户以 3000 积分兑换 POINTS 渠道的一件商品，余额变成 2000、库存确认消费并形成不可变流水。若后续无法履约，管理员冲正后新增 3000 分加分流水、库存恢复，历史扣分和原兑换单仍保留。
