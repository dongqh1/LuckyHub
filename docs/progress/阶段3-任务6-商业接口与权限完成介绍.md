# 阶段 3 / 任务 6：商业接口与权限

## 完成了什么

- 管理员可以创建优惠券模板、发券、创建会员产品和模拟支付结果。
- 普通用户可以查询自己的优惠券与会员，购买或续费会员，创建/查询/取消自己的商城订单，并创建支付单。
- 新增 9 个权限常量，与 V13 数据库权限完全对应。
- 四组用户接口都接入 JWT 登录过滤器和权限拦截器；未登录返回 401，无权限返回 403。
- 支付回调独立使用 `/callbacks/payments`，不要求用户 JWT，但必须通过支付签名校验。
- 用户购买会员时，`userId` 只从登录信息取得，前端不能通过请求体替别人购买或续费。

## 接口例子

登录后创建订单：

```powershell
$headers = @{ Authorization = "Bearer $token" }
$body = @{ orderNo = 'ORDER-1001'; skuId = 8; quantity = 1; userCouponId = 21 } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://localhost:8080/api/orders' -Headers $headers -ContentType 'application/json' -Body $body
```

创建模拟支付单：

```powershell
$body = @{ paymentNo = 'PAY-1001'; orderNo = 'ORDER-1001' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://localhost:8080/api/payments' -Headers $headers -ContentType 'application/json' -Body $body
```

管理员在本地环境模拟支付成功：

```powershell
$body = @{ result = 'SUCCESS' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://localhost:8080/api/admin/payments/PAY-1001/simulate' -Headers $adminHeaders -ContentType 'application/json' -Body $body
```

如果普通用户没有 `payment:simulate` 权限，请求最后一个接口会返回 403，避免用户自己把订单改成已支付。

## 测试结果

商业 Controller、真实过滤器/权限拦截器和原抽奖安全回归共 4 个测试全部通过，验证了 201/200、登录身份自限定、回调免 JWT、401、403 以及旧权限链不受影响。
