# 阶段 4 任务 8：阶段交付完成介绍

## 为什么有这个

功能测试通过不等于可以交接。数据库必须能从空库完整升级，旧模块不能回归，可执行 JAR 必须真的启动并发布 API，后续开发者还需要知道当前边界和下一步。因此最后一个任务把代码、数据库、运行产物和文档一起验收。

## 这是干什么的

本任务更新全局迁移守卫、API 手册、README、总路线和交接总结，提供可重复执行的空库验收脚本，并对阶段 4 做完整并发、全量、打包、OpenAPI、安全和代码审查。

## 具体实现

- 全局数据库契约已包含 V14/V15、39 张业务表和阶段 4 唯一索引。
- 旧 V5 历史权益迁移守卫的最终版本断言更新到 V15。
- `scripts/Verify-FreshMigration.ps1` 创建随机临时库、授予应用用户权限、运行 V1→V15、检查版本和表数，并在 `finally` 中撤销授权、删除且只删除该临时库。
- 新增 `docs/fulfillment-gateway-api.md`，包含权限、状态、四种 payload、六个操作、故障模式、错误码和 PowerShell 示例。
- README 标记数据库到 V15；总路线和交接总结将阶段 4 标为完成，并把阶段 5 抽奖奖励迁移设为唯一下一主线。
- 最终审查补出并修复一个边界：`attempt_count` 只统计 `EXECUTE`，`QUERY` 有独立尝试序号但不消耗执行上限。这样最后一次执行返回 UNKNOWN 时仍能完成必要对账。

## 举例解释

任务最多只允许执行一次。第一次调用会员供应方其实成功，但响应丢失：

```text
EXECUTE #1 -> UNKNOWN
attempt_count = 1 / max_attempts = 1
QUERY   #2 -> SUCCEEDED
attempt_count 仍为 1
```

查询是为了确认第一次执行结果，不是第二次发放，所以它保留审计流水但不应挤占执行次数。最终供应方只有一条会员记录。

空库脚本示例：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\Verify-FreshMigration.ps1
```

脚本成功输出 V15 和 39 张业务表，然后明确输出临时授权已撤销、临时数据库已删除。
