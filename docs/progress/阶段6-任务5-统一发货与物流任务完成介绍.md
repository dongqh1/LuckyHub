# 阶段 6 任务 5：统一发货与物流任务完成介绍

## 1. 为什么需要这一任务

阶段 6 的前几个任务已经让现金实物订单和积分实物兑换在下单时冻结了不可变地址快照，但“有地址快照”还不等于“已经发货”。如果现金支付、积分兑换和后续的抽奖领奖各自实现一套物流逻辑，就会出现三套重复状态机、三种幂等规则和三处隐私风险。

本任务增加统一 `shipping_order` 服务：三个业务来源只负责确认自己的前置条件，之后都使用同一张发货单和同一个 `LOGISTICS` 履约任务。这样将来替换真实快递供应方时，只需要替换 `LogisticsGateway`，不需要改支付、积分或抽奖业务。

## 2. 具体完成了什么

### 2.1 统一发货单与来源幂等

新增 `ShippingOrderService`、`CreateShippingOrderCommand` 和脱敏的 `ShippingOrderView`。

- `(sourceType, sourceId)` 最多创建一张发货单；
- 幂等重试会核对目标用户、地址快照、SKU、商品快照、数量和领取请求；
- 数据不一致时返回 `SHIPPING_IDEMPOTENCY_CONFLICT`，不会覆盖第一次发货信息；
- 发货单插入后生成稳定编号 `LOGISTICS-{shippingOrderId}`；
- `shipping_order` 与 `fulfillment_task` 在同一个本地事务中创建，任何一步失败都会一起回滚。

例如，发货单数据库 ID 为 `42` 时，无论支付回调重试多少次，履约编号始终是 `LOGISTICS-42`，数据库中仍只有一张发货单和一个物流任务。

### 2.2 现金支付和积分兑换接入

现金实物订单在支付成功并完成库存、优惠券确认后创建发货单；重复支付成功回调直接返回原支付结果，不会重复发货。虚拟商品保持原流程，不创建物流任务。

积分实物兑换在扣减积分、确认库存并完成兑换后创建发货单；重复兑换请求返回原发货关联。已经存在实物发货单的已完成兑换不能再执行积分冲正，避免“包裹已经发出，但积分和库存又被退回”的资产不一致。

### 2.3 履约表只保存脱敏信息

`LogisticsFulfillmentPayload` 现在只包含：

- 发货单 ID；
- SKU 和数量；
- 脱敏姓名、脱敏手机号和脱敏地区。

因此任务表和尝试表看到的是：

```text
张* / 138****5678 / 浙江省杭州市余杭区***
```

它们不会看到 `张三`、`13812345678` 或 `文一西路1号`。

### 2.4 明文只在 Gateway 调用前临时装配

`LogisticsRequestAssembler` 根据任务中的发货单 ID 读取发货单和不可变地址快照，核对用户、来源、SKU、数量和三项脱敏摘要，然后在真正调用 Gateway 前临时解密地址。

`LogisticsCreateRequest` 是显式实现的 final 类，不使用 record 或 Lombok 自动生成字符串；它的 `toString()` 永远固定为：

```text
LogisticsCreateRequest[REDACTED]
```

Worker 领取任务的数据库事务结束后才执行装配器和 Gateway，所以完整联系人只在内存中短暂存在。异常统一转换成不含个人信息的安全错误，明文不会进入任务、尝试、日志或错误摘要。

一个直观例子是：履约任务表只能看到 `张*`，而物流适配器在发送请求的那一刻可以在内存里读取 `张三`；请求结束后，系统不会把完整姓名重新写回数据库。

### 2.5 模拟物流使用安全 DTO

模拟物流没有直接序列化含明文的 `LogisticsCreateRequest`，而是先转换为只含发货单 ID、SKU、数量和脱敏字段的安全 DTO。`sim_logistics_record.request_payload` 与幂等指纹都来自同一个安全 DTO，既能保持模拟供应方幂等，也不会持久化完整地址。

### 2.6 履约状态投影

- 物流任务成功：发货单写入有界运单号并进入 `SHIPPED`；
- 任务进入 `QUARANTINED`：发货单进入 `FAILED`，保存最长 64/500 字符的安全错误码和摘要；
- 任务被终止：发货单进入 `TERMINATED`，即使旧任务没有错误文本，也会写入稳定安全摘要；
- 人工重试：原发货单和原履约编号保持不变，状态回到 `FULFILLING`。

抽奖来源的失败和终止状态投影接口已经保留，下一任务的领奖服务可以直接复用。

## 3. 测试证据

本任务严格执行了 RED → GREEN：

- 首次 RED：测试编译出现 9 个预期错误，原因是统一发货与受控装配接口尚不存在；
- 聚焦测试：`ShippingOrderServiceTests`、`PhysicalSourceShippingTests`、`LogisticsPrivacyBoundaryTests`、`FulfillmentWorkerTests`、`SimulatorGatewayTests` 共 13 项通过；
- 阶段 4 回归：`FulfillmentEndToEndTests`、`FulfillmentRecoveryTests`、`FulfillmentSafetyTests`、`GatewayContractTests` 共 12 项通过；
- 支付、积分、快照和履约接口兼容回归共 19 项通过；
- 随机临时空库执行 `clean test`：127 个测试类、445 项测试，0 failure、0 error、0 skip；
- 临时数据库授权已撤销，临时 schema 已删除，残留为 0。

额外验证覆盖了 Gateway 调用时无 Spring 数据库事务、任务和模拟表不存在完整姓名/手机号/详细地址，以及终止状态始终带有有界安全摘要。

## 4. 当前边界

本任务没有实现物流轨迹、验签回调、模拟事件推进、管理查询、退款、退积分、退货或真实快递账号接入，也没有修改 V1–V17 迁移。当前模拟物流只负责安全生成模拟运单，轨迹和签收将在任务 6 完成。

## 5. 下一步

下一步执行阶段 6 任务 4：让抽奖实物权益在领取期限内选择地址，创建不可变快照，并调用本任务的 `ShippingOrderService`。之后任务 6 再增加模拟物流事件、签名回调、轨迹幂等和最终签收。
