# 阶段 6 Task 6：运单轨迹与签名回调完成介绍

> 完成日期：2026-08-12

## 1. 为什么需要这一任务

Task 5 已经能为抽奖、现金订单和积分兑换统一创建发货单，并通过模拟物流获得运单号，但业务仍停在“已发货”。Task 6 补齐供应方轨迹回调、回放防护、单调状态推进和用户脱敏查询，使模拟物流与未来真实供应方使用同一条安全入口。

## 2. 实现内容

- 新增 `POST /api/shipping/callbacks/logistics`。只有“精确路径 + POST 方法”这个组合免用户 JWT/权限，安全性完全依赖时间窗、nonce 和 HMAC；同一路径的 GET/PUT 即使带有效 JWT，也仍要经过 shipping 权限检查，其他 `/api/shipping/**` 路由同样继续受保护。
- canonical UTF-8 文本固定为 `callbackId\nnonce\ntimestamp\nwaybillNo\neventType\neventTime`；枚举使用 `name()`，时间使用 `ISO_LOCAL_DATE_TIME`。
- HMAC-SHA256 使用 Base64URL 无填充传输。验签先 Base64URL 解码，再用 `MessageDigest.isEqual` 比较字节。
- 回调时间允许配置的前后五分钟窗口，过去或未来越界均拒绝；callbackId、nonce、waybillNo 只允许常见的 ASCII 字母、数字、点、下划线、冒号和短横线，拒绝首尾空白、换行及其他控制字符。验签、摘要、数据库查询和持久化均使用这个未经 `trim` 二次改变的同一表示。
- 单事务内先登记 callbackId/nonce 摘要，再按运单加锁，写入唯一供应方事件，并按状态等级单调推进。相同 callback 或供应方事件幂等，不同 callback 复用 nonce 判为重放；未知运单只写安全拒绝审计。已拒绝的同一 callback 重试时，从收据中的枚举化安全错误码恢复首次结果，不会把“状态冲突”改报成“运单不存在”。
- 模拟器管理接口生成随机 UUID callbackId/nonce，用本地 signer 签名后只调用 `LogisticsCallbackService`，不直接修改发货单或轨迹表。
- 用户查询只能读取本人的发货单，返回冻结快照中的脱敏姓名、手机号、地区和按 `event_time,id` 稳定排序的不可变轨迹，不返回地址密文、nonce、签名或回调审计内部字段。

## 3. 接口与状态

支持供应方事件：`PICKED_UP`、`IN_TRANSIT`、`OUT_FOR_DELIVERY`、`DELIVERED`。

状态映射：

- `PICKED_UP -> SHIPPED`
- `IN_TRANSIT / OUT_FOR_DELIVERY -> IN_TRANSIT`
- `DELIVERED -> DELIVERED`

发货单只前进不回退。抽奖实物发货单到达 `DELIVERED` 时，关联权益同步为 `DELIVERED`；现金订单和积分兑换仍保留各自支付或资产状态，物流状态从发货单单独读取。

用户接口：

- `GET /api/shipping/orders/{shippingNo}`
- `GET /api/shipping/orders/{shippingNo}/tracking`

模拟器接口：

- `POST /api/admin/simulators/logistics/{fulfillmentNo}/events`

## 4. 乱序示例

包裹先收到 `DELIVERED`，发货单和抽奖权益均进入 `DELIVERED`。两小时后供应方迟到发送旧的 `IN_TRANSIT`：系统仍把该事件追加为不可变审计轨迹，但状态等级检查阻止发货单和权益回退，因此用户看到的最终物流状态仍是 `DELIVERED`。

签名文本用换行分隔字段，因此签名字段本身绝不能夹带换行。通俗地说，`callbackId="A\nB", nonce="C"` 和 `callbackId="A", nonce="B\nC"` 拼出来都是 `A\nB\nC...`；若允许这种输入，一枚签名就可能被解释成两组不同字段。现在入口会在验签和落库前直接拒绝这类值，也拒绝看起来相同但首尾多空格的 callbackId，避免“签的是原值、存的是 trim 后值”。

权限豁免也按动作而不是只看地址：物流供应方只能匿名执行精确的 POST 回调。GET/PUT 不是回调动作，即使 URL 一样、JWT 有效但没有 shipping 权限，仍返回 403；测试为它们注册了真实 handler，所以结论不依赖 404/405。

## 6. 边界

- 不保存或记录原始 nonce、签名和 canonical payload，只保存摘要及安全错误。
- 不修改 V1-V17，不新增真实物流供应商，也不实现 Task 7 的管理员重试、终止和列表接口。
- 保留 Task 5 的隐私与事务边界：完整收件信息只在受控装配器到 Gateway 的内存中短暂存在，Gateway 调用仍在数据库事务外。
