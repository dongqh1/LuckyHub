# 阶段 6 任务 3：不可变地址快照与实物下单

## 为什么需要不可变快照

地址簿表达的是“用户现在的地址”，订单表达的是“用户下单当时确认的地址”。如果发货时重新读取地址簿，用户下单后修改或删除地址，就可能让历史订单被发往错误地点。因此，现金购买实物和积分兑换实物必须在下单事务里冻结一份不可变快照。

快照也保护隐私边界：订单查询只返回姓名、手机号和地区的脱敏摘要，不返回明文，也不返回六个加密字段。

## 具体实现

- 现金订单和积分兑换命令新增可空 `addressId`；实物商品必须提供，虚拟商品必须不提供。
- `ShippingAddressSnapshotService` 校验地址属于当前用户且为 `ACTIVE`，直接复制地址簿已有的六个密文和三个脱敏值，不进行解密或重新加密。
- 业务订单插入并获得数据库 ID 后，以 `CASH_ORDER/POINTS_REDEMPTION + 订单ID` 创建唯一快照，再条件更新订单的 `address_snapshot_id`。整个过程处于原下单事务中，后续库存、积分等步骤失败时，订单和快照一起回滚，不留下孤儿数据。
- 同一来源重复创建时，只有用户、原地址 ID 和所有复制内容完全一致才返回原快照；换地址或地址内容已变化会返回 `SHIPPING_IDEMPOTENCY_CONFLICT`。
- 现金订单和积分兑换视图新增可空 `addressSnapshot` 与 `shippingOrderId`。本任务的快照视图只包含快照 ID、快照编号和三个脱敏字段。
- 旧的支付、优惠券、会员折扣、库存和积分扣减/冲正语义保持不变；V1–V17 没有任何修改。

## 业务例子

小张购买一个实物商品，下单时选择杭州地址：

```text
张* / 138****5678 / 浙江省杭州市余杭区***
```

订单创建后，系统把当时地址簿中的密文与脱敏摘要复制到快照。第二天小张把地址簿改成上海，甚至删除杭州地址，订单快照仍保持杭州内容，后续包裹仍按下单时确认的杭州地址处理。新订单则可以选择更新后的上海地址。

如果小张用同一个订单号重试但换成另一地址，系统不会静默覆盖第一次选择，而是返回幂等冲突，避免同一订单出现两个收货意图。
