# 阶段 4 任务 5：租约与事务外调用完成介绍

## 为什么有这个

后台通常会运行多个 Worker。如果它们同时看到同一条待处理任务，可能重复发券或重复创建物流单；如果调用供应方时一直占着数据库事务，慢接口又会长时间占用连接和锁。租约机制同时解决“谁来处理”和“处理期间不占事务”两个问题。

## 这是干什么的

`FulfillmentStateService` 在短事务中领取到期任务，为每条任务生成随机租约令牌和过期时间。事务结束后，`FulfillmentWorker` 才调用 Gateway；调用完成后再开一个短事务，用原租约令牌记录结果和尝试明细。

## 具体实现

- `claimDue` 使用 `FOR UPDATE SKIP LOCKED`，多实例不会互相等待，也不会领取同一任务。
- 每次领取生成不可猜测的 UUID 租约令牌，并把任务切换到 `PROCESSING`。
- `FulfillmentClaim` 是不可变快照，包含类型、目标用户、JSON 内容、执行/查询操作和租约。
- Worker 按类型还原强类型 payload，再路由到对应 Gateway。
- Gateway 调用发生在领取事务结束后；异常只转换为可重试安全结果。
- `recordResult` 锁定单条任务并校验租约，写入一条 `fulfillment_attempt`，旧令牌不能提交结果。
- 成功、未知、可重试、永久失败分别转入成功、对账、等待重试或隔离状态。

## 举例解释

Worker A 和 Worker B 同时扫描 `FUL-001`：A 先锁到该行并写入令牌 `token-A`，B 使用 `SKIP LOCKED` 跳过。A 释放数据库事务后调用券系统，期间没有持有数据库连接。若 A 成功，只有 `token-A` 能写入结果；即使旧进程拿着 `token-old` 晚到，也会收到 `52005` 租约冲突，不能覆盖新结果。

## 测试证据

- 红灯：测试最初因 `FulfillmentClaim`、状态服务和 Worker 不存在而编译失败。
- 绿灯：3 个测试全部通过，覆盖 20 个并发领取者只有一个成功、旧租约无法完成、Gateway 观察到事务未激活，以及成功只生成一条尝试记录。
