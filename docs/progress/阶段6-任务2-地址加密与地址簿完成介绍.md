# 阶段6任务2：地址加密与地址簿完成介绍

## 为什么要做

收货人、手机号和详细地址属于高敏感个人信息。地址簿既要支持用户维护与默认地址切换，又不能让明文进入数据库持久化、接口响应或日志。本任务因此把“可使用”与“最少暴露”同时作为设计目标，并为后续实物领奖流程提供独立的地址所有权校验入口。

## 实现内容

- 使用 JCA `AES/GCM/NoPadding` 分别加密收货人、手机号、省、市、区和详细地址。每次加密使用 12 字节随机 nonce、128 位认证标签，并把密钥版本作为 AAD。
- 密文信封固定为 `版本.无填充Base64URL(nonce).无填充Base64URL(ciphertext+tag)`。生产密钥和回调密钥只从环境变量读取，不提供生产默认值。
- 配置绑定会校验 AES-256 密钥长度、密钥版本、各时间窗口、回调密钥字节数和批量大小；解析、版本和认证失败统一转换成不回显输入或密钥的安全业务异常。
- 地址接口只返回 `receiverMasked`、`phoneMasked` 和 `regionMasked` 等脱敏视图，不返回明文或密文。示例脱敏结果为 `张*`、`138****5678`、`浙江省杭州市余杭区***`。
- 创建、更新、软删除和设为默认均先以 `SELECT id FROM sys_user WHERE id=? FOR UPDATE` 锁定用户行，再读取或修改地址，从而串行化同一用户的地址变更。首个有效地址自动成为默认地址，并发创建或并发切换后至多保留一个有效默认地址。
- 所有地址接口要求登录并精确具备 `shipping:address:manage` 权限；跨用户操作返回 `ADDRESS_ACCESS_DENIED`，不存在或已删除地址返回 `ADDRESS_NOT_FOUND`。

## 随机 nonce 示例

以下示例使用测试专用非生产密钥，对同一个省份 `浙江省` 连续加密两次：

```text
第一次：v1.Vfzsqcn1vIrU3a5K.tlajtP9cMkQ2LouMI7_uRvUXW3LkPsG_Uw
第二次：v1.cJIKVT_2CcmFzJDH.MqgCYU3v2K_0WyJtq4690ivJt7j4vkho8A
```

两段密文不同，但同一完整地址在接口中的区域掩码始终是 `浙江省杭州市余杭区***`；两段信封均可解密回原值。

## 边界与下一步

本任务没有新增或修改数据库迁移，也没有实现地址快照、领奖、发货单、物流任务或回调。下一步应在后续独立任务中创建不可变地址快照，并把领取、履约和物流状态机建立在快照之上，避免发货过程受地址簿后续编辑影响。
