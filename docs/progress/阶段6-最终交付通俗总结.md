# 阶段 6 最终交付通俗总结

## 一句话说明

LuckyHub 现在能把“抽中的实物、现金买的实物、积分换的实物”安全地送进同一条发货流程：用户地址被加密，订单保留当时的地址快照，系统只创建一张发货单，模拟物流回传轨迹，用户和管理员看到的是脱敏信息。

## 为什么这次交付可信

我们不只验证了几个按钮。最终验收模拟了一位新开发者真正接手项目：

```text
新电脑 + 空数据库
  -> Flyway 从 V1 顺序跑到 V17
  -> 得到 48 张业务表
  -> 打包出唯一可执行 JAR
  -> 在空闲端口启动 JAR
  -> /v3/api-docs 看得到地址、领取、物流、回调、管理和模拟器接口
  -> 只停止本次启动的进程
```

这能排除两类常见假象：代码只在旧数据库上能跑，或者测试能过但打出的 JAR 根本起不来。

## 用户实际经历什么

- 抽中实物：先看到待领取；提交本人地址后才生成发货任务，过期未领会安全回补库存；
- 现金购买实物：下单时选地址并冻结快照，支付成功后创建发货单；
- 积分兑换实物：扣积分、确认库存、冻结快照并创建物流，重复请求不会重复扣；
- 三条流程随后都由同一个物流 worker、同一套签名回调和同一套 tracking 查询推进到签收。

例如用户下单时地址是杭州，后来把地址簿改成上海，这个旧包裹仍按杭州快照发货；但 API 和任务表只显示脱敏字段，完整地址只在调用物流 Gateway 前的受控内存中短暂解密。

## 安全规则

1. 地址簿与快照中的敏感字段使用 AES-256-GCM；
2. 用户不能读写别人的地址或发货单；
3. 同一来源、同一领取 requestId、同一回调和 nonce 都有幂等约束；
4. `DELIVERED` 后迟到的运输中事件可以作为历史轨迹保存，但不能把状态退回；
5. 领取与过期同时发生时只有一方成功，库存最多回补一次；
6. 日志、履约 payload、模拟器记录和安全错误不保存明文收件信息或 secret。

## 还没有什么

当前物流供应方是本地模拟器。项目没有真实快递账号、电子面单、运费、多仓，也没有退款、退货、换货和售后工单。这些是明确边界，不应被描述成已经完成或已排期。
